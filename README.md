# دیده‌بان تصویر · Vision Watcher

خبرنامهٔ فارسی تحلیل تصاویر واقعی، بینایی ماشین و هوش مصنوعی، همراه با معرفی فناوری‌ها و پروژه‌های تازهٔ گیت‌هاب. گزارش‌ها در Markdown تاریخ‌دار نگهداری و با Python به سایت استاتیک تبدیل می‌شوند. تاریخ شماره‌ها خورشیدی و فونت سایت وزیرمتن است.

سایت فعلی: [visionwatcher.vercel.app](https://visionwatcher.vercel.app/)

## شروع با هر مدل زبانی یا عامل جدید

**[پرامپت کامل راه‌اندازی و اجرای گزارش روزانه](DAILY_BRIEFING_PROMPT.md)** بدون نیاز به تاریخچهٔ چت، تنظیم زمان‌بندی، جست‌وجو و انتخاب، بررسی منابع، تولید گزارش، قالب، جلوگیری از تکرار، CI، PR، مرج، استقرار و انتقال به مالک جدید را توضیح می‌دهد.

این دستور را همراه لینک مخزن به مدل دارای ابزار بدهید:

> فایل DAILY_BRIEFING_PROMPT.md این مخزن را بخوان و فرایند گزارش روزانه را طبق آن راه‌اندازی یا ادامه بده. تنظیمات briefing.config.json، دسترسی‌ها و زمان‌بند موجود را بررسی کن؛ کارهای مجاز را خودت انجام بده و فقط پیش‌نیازهای واقعاً مفقود را از مالک بخواه.

| فایل | کاربرد |
|---|---|
| [DAILY_BRIEFING_PROMPT.md](DAILY_BRIEFING_PROMPT.md) | مرجع کامل تحریریه و اجرای عامل، مستقل از مدل |

**اتصال به ریپو به‌تنهایی زمان‌بند یا مجوز سرویس‌ها ایجاد نمی‌کند.** مدل به ابزار جست‌وجوی وب، GitHub با دسترسی مجاز و runner/زمان‌بند نیاز دارد. ورک‌فلوی موجود فقط سایت را تست/بیلد می‌کند؛ تولید گزارش و زمان‌بندی بیرون از مخزن انجام می‌شود. فایل config به‌تنهایی کد اجرایی یا زمان‌بند نیست. عامل باید سرویس لازم را متصل و راه‌اندازی واقعی را تأیید کند.

## قرارداد گزارش

اجرای هدف ۰۰:۰۵ تهران برای روز کامل پیش از زمان برنامه‌ریزی‌شده است؛ اجرای دیرهنگام همان روز هدف را حفظ می‌کند. هدف تا ۱۰ پژوهش، ۵ خبر بینایی ماشین، ۵ خبر هوش مصنوعی و مجموعاً تا ۵ پروژهٔ مرتبط است. موارد قدیمی یا کم‌ارتباط برای تکمیل تعداد اضافه نمی‌شوند.

در گیت‌هاب، پیشرفت فنی مهم همان روز یا پروژهٔ تازه با انتشار در ۳۰ روز اخیر و شاهد توجه در ۷ روز اخیر انتخاب می‌شود؛ این استثنای زمانی با تاریخ واقعی مشخص می‌شود. کامیت معمولی یا تعداد کل ستاره دلیل انتخاب نیست. تولید تصویر/ویدئوی مولد و ویرایش خلاقانه از همهٔ بخش‌ها حذف‌اند. جزئیات در پرامپت مرجع است.

مسیر محتوا `content/briefings/`، آخرین شماره `/`، آرشیو `/archive/` و نشانی دائمی هر شماره `/issues/YYYY-MM-DD/` است. کلید مسیر و فایل تاریخ خورشیدی با ارقام لاتین است. شمارهٔ منتشرشده خودکار بازنویسی نمی‌شود.

## استقرار روی Vercel

تنظیمات در `vercel.json` است: دستور ساخت `python3 build.py` و خروجی `dist`. مخزن و شاخهٔ main را به پروژهٔ Vercel خود متصل و استقرار خودکار را فعال کنید. نتیجهٔ build و deploy را جدا بررسی کنید. مطالعهٔ عمومی گزارش‌ها به کلید مدل یا حساب کاربری نیاز ندارد؛ تولید گزارش و بوکمارک وابستگی‌های جدا دارند.

## اجرای محلی و Docker

```sh
python3 -m unittest discover -s tests
python3 build.py
python3 -m http.server 8080 --directory dist
```

یا:

```sh
docker compose up --build -d
```

سایت محلی در `http://localhost:8080` است. برای استقرار Docker/هم‌روش، ریشهٔ ساخت `.`، فایل `Dockerfile`، پورت داخلی `8080` و مسیر سلامت `/healthz` است. اتصال Git و دامنه را در سرویس مقصد خودتان تنظیم کنید. CI در `.github/workflows/container.yml` ساخت Docker، مسیرهای عمومی، PWA و بوکمارک با SDK mock را می‌سنجد؛ صحت خبر و ورود واقعی Google جدا بررسی می‌شوند.

## فورک و مالک جدید

مقصد و دامنه را در config جایگزین و زمان‌بند مستقل تنظیم کنید. کلید عمومی `auth-public.json` به دیتابیس مالک اصلی اشاره می‌کند؛ برای کاربران خود پروژهٔ Supabase و Google OAuth مستقل بسازید. تگ مالکیت Google در `build.py`، هویت/راه تماس صفحات `legal.py`، نام/لوگوی PWA و callbackها را بررسی و برای خودتان تنظیم کنید. مجوزها و دسترسی‌های مالک اصلی به فورک منتقل نمی‌شود. فرایند کامل مهاجرت در پرامپت مرجع است.

## نصب روی گوشی و صفحه‌های عمومی

روی HTTPS، در Chrome اندروید گزینهٔ نصب یا Add to Home screen؛ در Safari آیفون Share → Add to Home Screen را انتخاب کنید. صفحات عمومی بازدیدشده برای آفلاین ذخیره می‌شوند و هنگام اتصال از شبکه تازه می‌شوند؛ مسیرهای بازدیدنشده ممکن است آفلاین موجود نباشند. درخواست‌های خصوصی Supabase و کدهای OAuth در کش PWA ذخیره نمی‌شوند.
